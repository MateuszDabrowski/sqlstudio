# Changelog

All notable changes to SQL Studio are documented in this file.

## 1.3.0 - 2026-10-13

1.3.0 saves a run's results into an existing Data Extension, with Append, Update or Overwrite, from the same Save to DE button. Lint no longer reports a syntax error for four kinds of SQL that Marketing Cloud Engagement runs. They are GROUPING SETS with an empty set, a join in parentheses, a join hint and TABLESAMPLE. Join to the query and Format read them too, and four small fixes come with them. A tab that keeps several queries, apart by blank lines, no longer gets a false syntax error at the second one, and Format lays out all of them. Lint also reports more of what Marketing Cloud Engagement refuses. That covers the WINDOW clause, a VALUES table and window functions written in a way SQL Server cannot run. It also covers the query's own ORDER BY with no TOP, and a SELECT in parentheses at the start or after a table's (. A SELECT in parentheses next to UNION, which T-SQL allows, no longer gets a false syntax error where Marketing Cloud Engagement runs it. It also brings SF MCE SQL, a companion skill that gives Claude the same lint, fixes and Format, from Help > Write SQL with Claude. This release changes the Frontend and the Backend, so both need their code replaced. The Cloud Page changes only its version number.

### Highlights

- **Save to an existing Data Extension:** Save to DE now adds to, updates or replaces the rows of one you already have. For a new one, it picks the right field types more often and starts in the folder you saved into last.
- **Massive lint improvements:** it catches more of what Marketing Cloud Engagement refuses before you click Run, such as tables separated by commas, a window function in WHERE and newer SQL Server functions, mostly with a one-click fix. Valid SQL such as GROUPING SETS no longer gets a false error.
- **Several queries in one tab:** keep the queries you run one after another together in a single tab, for a quicker comparison. Select one and Run sends just that query, while Format applies my style guide to all of them at once.
- **UI improvements across the board:** every list works from the keyboard, Open keeps its list for the session, Validate and Format say what they did in Status, and results grey out when you edit the query after a run.
- **New Claude skill:** SF MCE SQL gives Claude SQL Studio's lint, fixes and Format, the Data Views and my style guide. Get it from Help > Write SQL with Claude, or from mateuszdabrowski.pl/sql-studio.

### What is in it

- **Save to an existing Data Extension:** Save to DE opens with a choice at the top, New Data Extension as before or Existing Data Extension. Existing lists the Data Extensions a move can write, the Business Unit's own and the parent's shared ones, each with its folder and key. It leaves out synchronized ones, tables whose names start with an underscore, temporary Data Extensions and SQL Studio's own. Choosing one loads its fields. You then choose Append, Update or Overwrite, and none is chosen until you do. Each result column goes to the field of the same name, without regard to case, and every other column starts on Leave out, with a list of the fields no other column has. Save stays off, with the reason marked, while no column goes to a field, while a field that cannot be empty has no column and, for Update, while a primary key field has none. Values on screen that will not fit their field, such as a Text longer than its length or a value that is no e-mail address, warn and leave Save on. Overwrite asks first, with the number of rows the Data Extension holds and Cancel in focus. A toast says what was done: "Added 250 rows to Bounces_2026-10.", "Updated Bounces_2026-10 from 250 rows." or "Replaced the rows of Bounces_2026-10 with 250 rows." The Backend refuses an Overwrite that was not confirmed, a Data Extension that is named otherwise now than when you chose it or is another one under the same key and name, a synchronized one, a temporary one and SQL Studio's own, and it writes with your own token, so what Marketing Cloud Engagement lets you write is what it writes. Save to a new Data Extension works as it did. It is on by default, and an admin turns it off with one line in the Backend's settings, `var existingTargets = false;`, as such a move writes into the Data Extension at once (docs/DEPLOYMENT.md, step 7).

Save As shows it the same way, where the prompt to search was, while the search is empty or after Escape. A click or Enter on a Data Extension now closes the list on it, in both dialogs. Save As kept the matches on show. The box has the tooltip look only while the matches are on show. Before, a click on a Data Extension chose it and left what looked like an open list of one row, which did nothing when clicked. The arrow keys move through the matches in Save As as they do in Save to DE. ArrowDown and ArrowUp highlight an option and open a closed list, Home and End go to the first and the last, and Enter chooses the highlighted option. Escape closes the list and keeps what you typed, and a second Escape closes the dialog. The mouse highlights the option it moves over, and a click chooses it. In these searches and in the Folder box, Shift+Home and Shift+End select what you typed, as in any other text box. The lists of Open and History keep their look and take the same highlight and the same keys. ArrowDown and ArrowUp, Home and End move the highlighted row, Enter opens the query or loads the entry as a click does, and Escape closes the panel. Open's QUERY badge is easier to see in the dark theme. The rows no longer take the focus with Tab, as the search keeps it. In History, the arrow keys show the highlighted entry's tip with the start of its SQL, as the mouse does. In Open, a letter now filters the rows on screen at once, by name and target, without regard to case. Before, each letter cleared the list to Loading... and asked again. Marketing Cloud Engagement is still asked 200 ms after the last letter, in the background. Searching... is a quiet line under the list meanwhile, and the answer is drawn when it comes. A late answer to an earlier text is dropped. The rows that match by target alone stay when the answer comes. Open keeps its list for the session, as the sidebar keeps its Data Extensions. A panel opened again shows the rows at once, with no Loading... and no request. Only a text you have not searched before goes to Marketing Cloud Engagement. A Reload button beside the search empties the list and asks again for the text in the search. Saving a query with SQL Studio empties it too, so the next panel lists it. An Enter or a click on a row now starts one load. While the query loads, the list is greyed out under a box in its middle that says Opening "name"... with a spinner. Clicks, Enter, the arrow keys, Home and End do nothing then, typing does not filter, and Reload is off. Escape still closes the panel, and the query still loads into the tab it was opened from. Save As's Folder is the same searchable box as the Folder of Save to DE, over the query folders. It takes the same keys and starts where the list did, on the SQL Studio folder, or on the root. The two Folder searches match what you type literally, in a folder's name or path. So `_` lists the folders with an underscore, such as `__Archive`, and `_Su` those that hold `_su`. The searches of Save As's list and Save to DE's Existing list match literally, as the Folder searches do, with underscores kept. They match a name, and a key only from three characters, where the key starts with them. A field name no longer counts there. Before, "D" listed nearly every Data Extension, by a D in its GUID key. How a save ends is also a line in the tab's Status now, "Save to DE: Updated Bounces_2026-10 from 250 rows.", for a new Data Extension and an existing one, and for a refusal or a failure as well, so it is still there once the toast has gone. The next run or Validate in the tab replaces it. The link to Contact Builder stays with the toast.
- **Save to DE, the Folder remembers the last save:** the form for a new Data Extension starts on the folder you saved into last in that Business Unit. It started on the top folder every time. Each Business Unit keeps its own, in your browser. A form you cancel, and a save Marketing Cloud Engagement refuses, remember nothing. A save into the top folder makes the top folder the start again. If that folder has been deleted since, the form starts on the top folder and forgets it. While the folders are still loading, the form shows the top folder and moves to the remembered one when they arrive, unless you have opened or used the Folder box by then.
- **Save to DE, the types of a new Data Extension:** the overlay drafts a type for more columns. Before, only a plain reference to a field of known type had one, and every other column was Text 254. Now a whole-number literal is a Number, and a literal with a decimal point is a Decimal of 18 digits or more: `74.98` is Decimal(18, 2). CAST and CONVERT give their target type. BIGINT is Decimal(19, 0), as a Number field holds 32 bits, and FLOAT stays Text. The date, counting and ranking functions give a Date or a Number, and SUM and AVG a Number or a Decimal. ISNULL, COALESCE, CASE and arithmetic follow SQL Server's rules. A column of a derived table, a CTE or a UNION gets the type of what is behind it, widened across the branches of a UNION. A text literal stays Text, also one that looks like a date, as SQL Server types it varchar. A Date is drafted only for text that converts to a Date field. SYSDATETIME, DATETIMEOFFSET and a DATETIME2 of more than 3 decimals of a second stay Text, and DATEADD takes the type of its date. A Decimal of more than 8 decimals, such as `74.98 / 3`, is never cut to the 8 a field holds, as that would round its values.
- **Save to DE, types from the values:** when every row of the run is on screen, a column that is still Text gets a type from its values. ISO dates of at most 3 decimals of a second give a Date, and whole numbers of an INT's range with no leading zero a Number. Decimal numbers give a Decimal, and e-mail addresses an EmailAddress. A leading zero (`00123`), a date that is not on the calendar (`2026-02-30`) and a page that holds only some of the rows keep a column Text. A column that passes a field of a Data Extension or a Data View through is never typed by its values, so a Text field of dates stays Text. That holds through a derived table, a CTE, a UNION, LAG, MIN and MAX. It also holds through ISNULL, COALESCE, NULLIF, IIF, CHOOSE, CASE, TRIM and a CAST to a text type. The move into the new fields is Marketing Cloud Engagement's own conversion, so change a field's type in the overlay when a draft is not what you want.
- **Save to DE, values a Number or a Decimal does not hold:** the overlay warns of a value on screen that a Number or a Decimal field does not hold, whether the draft gave the type or you chose it. A decimal or a date in a Number, and more whole digits than a Decimal's precision and scale allow, fail the move. More decimals than the scale are rounded by the move. Save stays on. When a move fails with no reason, the overlay names the values that fail it, and not those it only rounds.
- **Dates in the results grid:** a date passed through LAG, LEAD, FIRST_VALUE, LAST_VALUE, MIN or MAX, a derived table or a CTE keeps its field's type in the run. The grid shows it as the field does, `2026-03-02 00:00:00`, and no longer as `Mar 2 2026 12:00AM`. So does an expression whose value is exactly a datetime: `GETDATE()`, `GETUTCDATE()`, `CURRENT_TIMESTAMP`, a CAST or a CONVERT to DATETIME, and DATEADD over one of these or over a Date field. `SYSDATETIME()`, a CAST to DATE or DATETIME2, another function, SUM, AVG, arithmetic, CASE and a UNION stay Text in the run, as a wrong type there fails it. So do a LAG or a LEAD whose default could change the type, such as `LAG(o.Qty, 1, 0.5)`, and a subquery with FOR JSON or FOR XML. A run waits for the fields of a Data Extension inside a derived table or a CTE only when a typed column reads them.
- **GROUPING SETS:** `GROUP BY GROUPING SETS ((s.a), ())` no longer gets MCE000 at the empty set. A set of several columns, `(s.b, s.c)`, and ROLLUP or CUBE inside GROUPING SETS are read, and so are `GROUP BY ()` for the grand total alone and ROLLUP or CUBE with sets of columns, `ROLLUP((s.a, s.b), s.c)`. `GROUPING SETS ()` with no set, a GROUPING SETS inside another, a ROLLUP or CUBE inside a ROLLUP, a CUBE or a set of columns, as `ROLLUP(s.a, CUBE(s.b))`, and `GROUP BY a, (b, c)` stay errors, as SQL Server refuses them.
- **Joins in parentheses, join hints and TABLESAMPLE:** a join in parentheses, `INNER JOIN (B AS b INNER JOIN C AS c ON c.id = b.id) ON b.id = a.id`, or a FROM that opens with one, no longer gets MCE000. A derived table, `(SELECT ...) AS x`, keeps its own rules. A join hint between the join type and JOIN, `INNER HASH JOIN` or `LEFT OUTER MERGE JOIN` with LOOP, HASH, MERGE or REMOTE, is read, and so is `TABLESAMPLE [SYSTEM] (10 PERCENT)` or `(100 ROWS)` with `REPEATABLE (5)` after a table and its alias. A bare `HASH JOIN`, a join in parentheses with no ON, a hint before CROSS JOIN or APPLY, LOOP with a RIGHT or FULL join and REMOTE with any join but INNER stay errors, as SQL Server refuses them. The tables inside the parentheses count as tables of the query for the rules that read an alias, so a misspelled column of one of them gets MCE062, and a star next to such a join gets MCE008 as it does next to any join. The join inside the parentheses is read as any other: MCE071 names the keys it leaves out between two send-log views, MCE018 the missing `_APID`, and MCE017 a Text field compared with a Number.
- **Joins in parentheses, read by the lint:** the ON inside a join in parentheses, and the ON after one, are read by MCE071, MCE018 and MCE017 as a flat join's ON is: `_Sent s JOIN (_Open o JOIN _Click c ON ...) ON o.JobID = s.JobID` gets MCE071 for the three keys the join of _Open to _Sent leaves out. `FROM ((A AS a INNER JOIN B AS b ON ...))`, a join in two pairs of parentheses, no longer gets MCE000, and Format lays out a table hint inside parentheses.
- **Join to the query:** its sidebar buttons stay on for a query with a join in parentheses, a join hint or TABLESAMPLE. The tables inside the parentheses count among the query's tables, the join is written after the last join as for any query, and the tables above it still line up as Format lays them out.
- **Format:** a join in parentheses stays on the line of its join with its ON below it, a bare JOIN inside it is written INNER JOIN, a join hint stays in upper case before JOIN, and TABLESAMPLE stays on the table's line after its alias. GROUPING SETS, ROLLUP and CUBE are written in upper case, as `GROUP BY GROUPING SETS ((s.a), ())`. A join in parentheses that holds a subquery is left as it is, and Format says why. `WHERE a=- -1` is no longer left unchanged: Format keeps a space between a sign and a following sign, `a = - -1`, as `--` would start a comment.
- **MCE032:** a COALESCE or an ISNULL whose arguments can all be NULL, and a LEFT, RIGHT, CAST or CONVERT of a column, now get the NULL warning next to a text, as UPPER(s.a) does: `'Hi ' + COALESCE(s.a, s.b)`. One that cannot be NULL, such as `COALESCE(s.a, '')`, still gets none, and nor does a date written as text, `'Run ' + CONVERT(VARCHAR(10), GETDATE(), 120)`: GETDATE() and the other clock functions, NEWID(), COUNT, DATEADD and the date functions of values that cannot be NULL, and a sum or a join of texts inside a call, `RIGHT('0' + CAST(DAY(GETDATE()) AS VARCHAR(2)), 2)`, cannot be NULL. Nor can a date moved with AT TIME ZONE, TODATETIMEOFFSET or SWITCHOFFSET, as MCE034 advises them, or CHAR(13) and NCHAR of a code in range. A call that can be NULL before the +, as `LEFT(s.Name, 3) + 'a'`, now warns as one after it does.
- **MCE062 and a query of one table:** MCE062 now checks the columns of a query that reads one table and writes them with no prefix, the form the style guide recommends. `SELECT SubscriberKy FROM _Subscribers` gets MCE062 with the fix Change to SubscriberKey. The fix takes the one field nearest to the column, so SubscriberID, 2 edits away, no longer leaves SubscriberKey, 1 edit away, without a fix. Two fields at the same distance still give none. It read only `alias.column` before. The query itself and each branch of its top-level UNION, EXCEPT or INTERSECT are checked, each against its own table. A query with a JOIN, an APPLY, a comma or a derived table is not, as a bare name could belong to any of its tables. A subquery, a derived table and a CTE body are not either, as a bare name there can be a column of the outer query. A function call, a literal, `*`, a keyword and a variable are no column. The fixes are the same as for `alias.column`, and a fix to a field that starts with an underscore writes the alias too, `DeviceID` to `_DeviceID AS DeviceID`. A CTE with the name of a Data Extension no longer takes that Data Extension's fields for MCE062, for `alias.column` too.
- **A tab that keeps several queries:** queries one under the other with no `;` between them, which you select one of to run, no longer get MCE000 "There is extra text after the end of the query" at the second SELECT. Lint reads each query on its own and adds one note at the start of the second, MCE002: "This tab holds 3 queries, and a Query Activity runs one. Select the one to run: Run sends all of the text otherwise." Run of a selected query works as before, and Run of the whole tab is stopped with MCE002 as an error that says to select the query to run. Queries apart by `;` or by a GO line are read the same way, where MCE002 was an error in the editor. Validate of the whole tab asks you to select a query and sends no query check, as Marketing Cloud Engagement read three queries as one and answered with an old style JOIN error, for which SQL Studio blamed commas after FROM. With Run anyway the hint now says the text holds several queries. Format lays out every query and joins them with one blank line, keeps a `;` you wrote and adds none, and a comment at the end of a line stays with its query. MCE001 is judged for each query, and Fix all, Join to the query and the completions work in the query the cursor is in.
- **MCE074's Remove RETURNING fix:** it keeps a comment inside the clause. `JSON_ARRAY(a RETURNING /* keep */ JSON)` becomes `JSON_ARRAY(a /* keep */)`.
- **The WINDOW clause and IGNORE NULLS:** Marketing Cloud Engagement refuses SQL Server 2022's `WINDOW` clause, so lint rule MCE075 reports it, with a fix that writes each window's definition into the `OVER` that names it. `IGNORE NULLS` and `RESPECT NULLS`, as in `LAST_VALUE(x) IGNORE NULLS OVER (...)`, which Marketing Cloud Engagement runs, no longer get MCE000, and they take the keyword colour.
- **Window functions Marketing Cloud Engagement refuses:** new lint rule MCE076 reports them with SQL Server's own words. That covers a window function in WHERE, GROUP BY, HAVING or ON, or inside an aggregate, as in `AVG(DATEDIFF(DAY, LAG(...) OVER (...), ...))`. It also covers DISTINCT with OVER, ROW_NUMBER, LAG and the other ranking and offset functions with no OVER or no ORDER BY in it, and PERCENTILE_CONT with no OVER. `COUNT(DISTINCT x) OVER (PARTITION BY p)` gets a fix, in Fix all, that counts the same with two DENSE_RANKs.
- **VALUES:** `FROM (VALUES (1, 'a'), (2, 'b')) AS v(n, s)` gets MCE063, as Marketing Cloud Engagement reads VALUES as a Data Extension name. Its fix, in Fix all, writes the rows as `SELECT ... UNION ALL SELECT ...`.
- **ORDER BY on the query itself:** MCE013 now reports the query's own ORDER BY with no TOP, the one after a UNION included, as Marketing Cloud Engagement refuses it. Before, it reported one only inside a subquery or a CTE. Sort the results in the grid, or add TOP. Its Remove ORDER BY fix now takes the space or line break before it too.
- **A SELECT in parentheses beside UNION:** T-SQL lets each operand of UNION, EXCEPT and INTERSECT be a query in parentheses, with its own TOP and ORDER BY. Lint now reads such operands, so `(SELECT a FROM T) UNION ALL (SELECT a FROM U)` no longer gets MCE000. Nor do they get it in a derived table, a CTE, IN or EXISTS. A derived table of such operands takes its column names from the first operand, as with a plain UNION. MCE013 reports an ORDER BY with no TOP in an operand, and MCE053 a SELECT of another width in any of them. Format lays out the ones it read before, such as `WHERE EXISTS ((SELECT 1) UNION (SELECT 2))`, and says why it leaves the others. Marketing Cloud Engagement's query check runs such a SELECT after UNION and inside IN. It refuses one at the start of a query and right after `FROM (`, and new lint rule MCE077 reports both as errors. MCE077 also reports one after `JOIN (` or `APPLY (`, and a join in parentheses that opens with a derived table. Its fix takes the parentheses out where the query keeps its rows and their order without them. Where it cannot, it makes the SELECT a derived table, `SELECT b1.* FROM (...) AS b1`, which Fix all leaves to you. It does so when every column has a name of its own and nothing after the `)` names a table inside it. At the start of a query, the derived table repeats the SELECT's TOP before an ORDER BY. After `JOIN (` and `APPLY (`, a join in parentheses gets no fix, and the message says how to write it. MCE007's rewrite of a CTE whose body starts with a parenthesis takes these fixes too. The hints that follow the check's two answers name MCE077 when lint reports it.
- **MCE045's Filter to the last 30 days:** the fix writes its WHERE right after the table. It wrote `o  WHERE ... GETDATE())GROUP BY`, with two spaces before WHERE and none before GROUP BY.
- **Format and a SELECT in parentheses after a name:** Format leaves `SELECT a FROM T` with `(SELECT a FROM U)` on the lines below it as it is, and says why. It wrote `FROM T(SELECT a FROM U)`, which reads as a call and joins the two.
- **FOR JSON and FOR XML in a SELECT with no FROM:** Format wrote `FOR JSON AS PATH` for `(SELECT 1 AS a FOR JSON PATH)`, which no longer parsed. It now lays the clause out on a line of its own.
- **OFFSET and FETCH:** lint takes `FETCH FIRST` as `FETCH NEXT`, and `ROW` as `ROWS`, as T-SQL does. Each got MCE000.
- **Completion in a later branch of a UNION:** the columns and an alias come from that branch's own FROM. Completion read the first branch's tables in every branch, so an alias of a later branch could name the wrong table.
- **MCE007's Rewrite as a subquery:** for a query in Format's layout, the rewrite keeps the layout, with `FROM (` and `) AS name` where the style guide puts them. A CTE body on lines of its own keeps its lines under `FROM (`, also below a main query laid out by hand.
- **An error after an edit:** once a run fails, an edit that changes the query greys its error panel on the soft hatch of stale rows, and "Edited since this run" shows before the run summary, with a tip that says the error comes from the query as it last ran. A Validate error greys its panel the same way. The grey goes when the query matches again, as after an undo, and with the next run or Validate.
- **A ; in the query:** a `;` before the query, as in `;WITH ...`, or at its end, as in `SELECT ...;`, gets MCE002 as an error, as Marketing Cloud Engagement refuses both with "';' is a reserved word and may not appear in your query". Lint had let a `;` at the end pass. A fix in Fix all takes it out, and MCE007 and MCE013 still see the query behind a `;` before it. In a tab of several queries, a `;` between two still only ends the first. A hint follows MCE's error too.
- **A request that does not get through:** when the connection to Marketing Cloud Engagement drops, as "Failed to fetch" or no answer within 60 seconds, a run's error and Validate's now say what to do: try again in a minute, and reload the page if it keeps failing while other sites load, as the tabs and their results come back. Validate's failure shows in Status too, where it was a toast alone. And while the run gate stops Run on a tab of several queries, the Status list shows the error its panel counts.
- **A fix from its button in Status:** a toast now says it was applied, "Applied 1 fix: Count with DENSE_RANK.", as Fix all's does.
- **A focused field:** its border and its keyboard ring are now in the action colour, amber in the dark theme, the colour of a chosen option and of Save. They were red, the colour of an invalid field. A focused checkbox or radio has the same ring. Buttons, rows and links keep the primary ring, red in the dark theme, by choice: a red ring on Cancel reads as discarding what the view holds. The light theme looks as before, as its two colours are the same blue.
- **A Data Extension list that fails to load:** the sidebar's Reload and a search that starts the load no longer log an uncaught error beside the failure the sidebar shows with Retry.
- **SQL Studio installed in a child Business Unit:** the sidebar now says why the parent's shared and synchronized Data Extensions are missing. Installed in a child, SQL Studio cannot list them or give them fields, though queries on their `ENT.` names still run. Installed in the parent, one deployment lists them for every child, as step 6 of the deployment guide says.
- **Tables separated by commas:** new lint rule MCE078 reports `FROM A AS a, B AS b` as an error, as Marketing Cloud Engagement refuses it: "Old style JOIN (ANSI JOINs) syntax is not allowed." Its fix writes CROSS JOIN for each comma, which gives the same rows, and Fix all applies it. When a table after the comma starts with a query in parentheses, as `, ((SELECT 1 AS n) UNION ALL (SELECT 2 AS n)) AS q`, the same fix takes the parentheses out too, as the check refuses them after JOIN (MCE077). One click gives a query that runs, and Fix all leaves nothing behind. Where MCE077 has no safe fix for the table, the fix writes CROSS JOIN alone. With a RIGHT or FULL JOIN after the comma there is no fix, and the message says how to write the joins.
- **What SQL Studio adds to Marketing Cloud Engagement's errors:** the advice on tables separated by commas no longer follows the error of a query that starts with WITH, where it did not apply. New hints follow the errors for a VALUES table, an ORDER BY with no TOP, a window function in WHERE and DISTINCT with OVER, each with what to write instead.
- **Docs links:** the hover of a keyword or a function now links both the author's article (MD docs) and Microsoft's T-SQL reference (MS T-SQL docs), side by side, where both exist. Before, it linked one page. The details of its suggestion do the same. A keyword or function that no article covers links Microsoft's page alone. `Ent.` and `WITHIN GROUP` have no Microsoft page, so they link the article alone. EXCEPT, INTERSECT, COLLATE and WITHIN GROUP now link the author's articles. The window and JSON findings, and the hover docs of the window and JSON functions, link the new MCE SQL Window Functions and MCE SQL JSON Functions articles. The links for CHOOSE, IS NULL, IS NOT NULL and WITHIN GROUP went to Microsoft pages that do not exist. CHOOSE and the two IS NULL tests now go to the right pages, and WITHIN GROUP to the article.
- **A stray character in a select item:** `SELECT TOP 1 1 AS Position … ORDER BY Position` gets the one MCE000 at the stray character and no longer an MCE010 beside it. An MCE010 for another item stays. Any MCE000 inside an item takes that item's MCE010 along, until the error is fixed.
- **A Claude skill, SF MCE SQL:** a companion skill (named `sf-mce-sql`) that writes, fixes, reviews and explains SQL for Marketing Cloud Engagement Query Activities in Claude, also through an MCE MCP server. It runs SQL Studio's own lint, fixes and Format on each query, and compares the query with the fields of the Data Extensions you give it. A child run whose status is not there yet no longer ends on the first rows its page 1 shows, which can be a share of them while the query still writes: SQL Studio asks Marketing Cloud Engagement whether the query still runs, and reads page 1 again once it has finished. Cmd/Ctrl+A after Marketing Cloud Engagement's page had the keyboard focus, as it does after a reload and sometimes on its own, no longer selects that page and paints SQL Studio's frame blue: the frame takes the focus back when the pointer moves over it, and the editor takes it as soon as it is ready. A field list or a Data Extension list asked for when the session had lapsed now loads once the background renewal is done, where it used to need a second click or a page reload, and a request still in flight during a renewal no longer starts a second sign-in. While that renewal runs, an amber toast says so, and a green one says when it is done, or an amber one asks to try again what did not go through meanwhile, where the field list used to read "Loading fields..." for several seconds with no word why. A request that Marketing Cloud Engagement refuses with HTTP 429, as it did for a restored tab's results while four tabs asked at once, now waits and tries again up to three times, after about 1.5, 3 and 6 seconds, where that changes nothing (a run or a save is not sent again, and says to wait a few seconds and try again), and restored tabs read their results one after another, the tab on screen first.

## 1.0.0 - 2026-09-29

The first public release. SQL Studio rebuilds Salesforce Labs' Query Studio as a Cloud Page App that runs entirely inside your Marketing Cloud Engagement account, with each user's own login and permissions.

### Highlights

- Four query tabs that run at the same time, each on its own Query Activity.
- Lint for what Marketing Cloud Engagement refuses, with one-click fixes, and a formatter that follows the author's SQL style guide.
- Results that keep their types: dates with their seconds, sorted as dates, numbers sorted as numbers, paged, and exported in full to CSV.
- No server outside your account: every call runs with your own login, and the code is open to audit.
- Sessions stored hashed and encrypted, and renewed in the background while you work.

### What is in it

- **Editor:** T-SQL highlighting, completion for the System Data Views, your Data Extensions and their fields, the known values of status and category fields, and hover documentation that links to the author's field references, Salesforce's documentation and Microsoft's T-SQL reference.
- **Checks before a run:** Validate uses Marketing Cloud Engagement's own query check, so what passes and which functions work match Automation Studio's Query Activities. SQL Studio's lint adds what that check misses, such as an unpaired apostrophe in a comment, a `FOR JSON` at the top level, a column name a Data Extension field cannot have, or a Text column compared with a Number one, with a fix for most.
- **Runs:** four tabs, each with its own query, results and Status, kept in your browser per Business Unit and user. A run writes into a temporary Data Extension with a one-day retention, in a SQL Studio folder, and a column that names a Date, Number, Decimal or Boolean field keeps that type. A run that fails while it runs says so, with the cause SQL Studio knows for it.
- **Results:** a paged, sortable grid. The first 2,000 rows read without an API call, and later rows in 2,000-row chunks. Export CSV reads every row, reusing what is already loaded.
- **Saving:** Save as, Open and Save for Query Activities, with a check of your columns against the target Data Extension, and history in the browser or, if your admin turns it on, in a Data Extension.
- **Deployment:** one Cloud Page and two Code Resources, "SQL Studio", "SQL Studio Frontend" and "SQL Studio Backend", and an Installed Package. The first sign-in creates the sign-in log, and the app then creates the error log and the SQL Studio folders itself. The settings are checked before the first sign-in, and a mistake is named, never shown.
- **Security:** the sign-in log keys each session by a hash of its id, and stores each access token encrypted and bound to its own row and user. Browser storage is per user. There are no refresh tokens: `docs/EXTENDING.md` explains why, and what adding them takes.
- **Updates:** once a day, SQL Studio checks the public repository for a newer release and shows an Update badge with its key changes.
